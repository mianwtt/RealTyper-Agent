# 使用说明

## 环境与启动

需要 Windows、Python 3.9 或以上、微软拼音中文全拼。依赖见 [requirements.txt](../requirements.txt)。在项目根目录的 PowerShell 中执行：

```powershell
python -m pip install --target .deps -r requirements.txt
python -m pinyin_agent --quick
```

日常入口为 [快捷输入.cmd](../快捷输入.cmd)，本地验证台入口为 [启动.cmd](../启动.cmd)。启动器需要 `pythonw.exe` 可从 PATH 找到；若启动器没有打开窗口，先用上面的 `python` 命令查看错误。

默认 `--hybrid`：先用 jieba 本地词典生成完整计划，再通过本机 Ollama 的 `http://127.0.0.1:11434`、`qwen3.5:9b` 补充语义与读音。模型不得拆碎词典已确认的词语；单次模型等待最多 20 秒，连接失败、输出改写或超时会使用本地计划。超过 400 字符的原文直接使用本地计划，避免等待大段模型输出。程序不会自动下载模型。

```powershell
# 词典 + Qwen：默认模式
python -m pinyin_agent --quick

# 仅本地词典，不调用模型
python -m pinyin_agent --quick --offline

# 更慢的节奏
python -m pinyin_agent --quick --pace slow

# 指定你已安装并验证的模型
python -m pinyin_agent --quick --url http://127.0.0.1:11434 --model your-installed-model
```

`your-installed-model` 请替换为实际模型名称。当前集成的是 Ollama API。

## 快捷模式

1. 复制要输入的普通文字。
2. 点击其他应用输入框里的插入位置。系统需已启用微软拼音；检测到英文直输时会自动切换重试。已有文字无需清空。
3. 按 Ctrl+Alt+V。程序检查目标框、生成计划，然后开始输入。
4. 保持原输入框焦点。再按同键暂停或继续；Ctrl+Alt+Q 停止。

小窗口默认开启“置顶”，点击其他应用时仍可显示；拖动标题栏可调整位置，取消“置顶”可恢复普通窗口。置顶只改变窗口显示层级，目标输入框仍可获得键盘焦点。小窗口最小化后快捷键仍然生效，关闭窗口会退出并释放快捷键。暂停在当前片段完成后的检查点生效，停止保留当时已输入的内容。规划期间停止会阻止后续按键；已经发出的模型请求可能需要等待返回。

当前快捷模式要求目标可编辑、可读取，并能提供准确光标位置；拒绝密码框、只读框及无法可靠定位的控件。单次原文最多 20,000 字符，Tab 等控制字符会被拒绝。浏览器先支持单行原文；原生多行 Edit／RichEdit 可处理换行。切换窗口或输入框会停止任务。

启动时记录插入位置，将本次新增内容作为独立任务范围。差异比较、回删、修正和最终复制均只覆盖本次内容；原有前后文用于定位范围，不发送给模型。已有选区会先收起到末尾，保留选中文字后再输入。运行期间请保持焦点，不要手动移动光标或编辑正文；检测到原有前后文变化时停止进一步操作。

## 本地验证台

运行 `python -m pinyin_agent`：

1. 输入原文，或点击“读取剪贴板”。
2. 默认使用词典与 Qwen 结合，也可选仅本地词典；需要时检查模型连接。
3. 点击“生成计划”，检查词组与拼音。生成后原文如有变化，需要重新规划。
4. 选择“舒缓／自然／较快”节奏，在空白测试编辑器中开始拼音录入。
5. 结束后检查“全文一致”状态和候选核验记录；结果会复制到剪贴板。

验证台的“校验并修正”用于对已有测试文本执行差异定位与重输。“停止”按钮或 F12 可终止任务；外部输入建议使用 Ctrl+Alt+Q，以便明确发送停止请求。

## 词组规划与候选选择

词典先保护“工程师”“射频电路”等完整词语，Qwen 在这些边界上补充规划。程序检查原文完整性、数量与拼音，模型读音缺失或格式错误时使用上下文词典补正；模型改写或计划不可用时回退本地计划。`lexicon.txt` 可增补词语，`pronunciations.json` 可维护特殊读音，`typing_hints.json` 可保存经过实测的辅助词，例如用“回天乏力”取得“乏力”。未知词语和多音字仍可能需要人工检查。

汉字通过实际拼音字母按键进入系统输入法，音节用英文单引号分隔。选词优先使用可用的原生候选接口；当前机器的微软拼音主要通过上屏反馈验证：

1. 输入拼音并确认一个候选。
2. 回读输入框实际文字，与目标片段比较。
3. 不一致时删除本次新增文字，重新输入拼音再选择。

每片段最多确认三次，候选、英文状态恢复及后续纠错共享额度，不再翻多页或拆字续试。可用词带字、短语带词；辅助选词失败后第三次改试其他候选，只留下经实际回读确认的目标片段，辅助部分通过 Backspace 去除。正常末尾重试优先直接退格，需要定位时先验证范围并等待浏览器确认；键盘定位前等待用户松开快捷键。缓存命中仍然核验。

正常录入不使用 OCR，也不会依靠截图让模型逐次选字。英文、数字、标点和 emoji 使用字符事件；汉字只经过拼音按键与候选确认。外部快捷模式每个片段后仅对比本次累计新增文字，最后只导出本次实际内容到剪贴板并读回比较；光标保留在新增内容末尾。

## 输入节奏

| 模式 | 相对节奏 |
| --- | --- |
| `slow` / 舒缓 | 比自然档更慢，便于观察输入过程 |
| `natural` / 自然 | 默认档，随机按键间隔与词间停顿 |
| `brisk` / 较快 | 缩短等待，仍保留随机波动 |

自然档按键延迟采样基准约 150 ms，范围 55–390 ms；词间停顿约 0.20–0.64 秒。按键、词间、标点和句末仍随机变化，偶尔有较长停顿。实际总耗时还包含输入法响应和候选重选。

这些是可调的节奏规则，未使用真人按键数据拟合。`timing_summary` 记录采样的按键与停顿统计。

## 数据与日志

模型规划请求发往你配置的 Ollama 服务，默认地址在本机。汉字片段及所需上下文用于分词和读音规划；规则模式不调用模型。程序在 `runs/` 保存原文、计划、候选重试、差异修正与结果，因此日志中会包含录入内容。

最终复制从输入框读取本次实际输入的文字，不用原文代替结果，也不通过全选移动光标。验证台的独立任务核对测试编辑器；外部快捷任务只核对其新增范围。浏览器字符输入会等待实际回读，避免无障碍值更新较晚导致重复输入。

## 常见问题

**快捷键没反应？** 确认快捷窗口仍在运行。重复实例或其他应用占用快捷键时，窗口会给出提示。先点击目标输入位置，再按快捷键。

**出现英文拼音或提示未进入中文候选？** v1.0.4 会先撤回本次误输入，再自动切换已启用的中文输入法或按微软拼音默认 Shift 切换一次，随后重试。若系统没有已启用的中文输入法，或自定义设置禁用了 Shift 切换，会停止并提示手动处理；不会反复盲目切换。

**候选为什么会重试？** 微软拼音的词库、上下文与自学习会改变候选位置。程序通过上屏结果核验，不能保证每次第一项就是目标词。

**能用于 Word、任意网页或复杂文档吗？** V1 未保证这些环境兼容。优先使用已验证类型的普通编辑框，复杂文档和自绘编辑器需要额外适配。

**已有正文时从哪里输入、检查哪些内容？** v1.0.2 从启动快捷键时的光标位置插入，只对比、修正和复制本次新增内容。若控件无法提供准确光标位置，会给出提示，避免猜测位置。

## 验证命令

```powershell
python -m unittest discover -s tests -v
python -m pinyin_agent --smoke --offline --text '发力、法力、乏力'
python tests/windows_acceptance.py
python tests/external_acceptance.py --case native
python tests/external_acceptance.py --case model
python tests/external_acceptance.py --case nonempty
python tests/external_acceptance.py --case focus
python tests/external_acceptance.py --case pause-stop
python tests/external_acceptance.py --case pause-resume
python tests/external_browser_acceptance.py
python tests/external_browser_acceptance.py --multiline
```

实际输入验收会打开自有测试窗口并发送按键，运行期间保持其焦点。浏览器多行用例验证的是提前拒绝，不能当作多行已支持。完整历史结论见 [VALIDATION.md](../VALIDATION.md)。
